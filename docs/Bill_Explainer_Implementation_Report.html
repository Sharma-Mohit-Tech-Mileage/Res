1. Overview

Purpose: This document explains how Bill Explainer is fetched, gated, rendered in Billing Breakdown, and opened from the app.

Primary Screen: Billing Breakdown screen.

Primary Endpoint: api/GetBillExplainer/Get.

User Outcome: If eligible, user sees a "Bill Explainer" link and opens the target URL.

Key Functional Summary

  • Screen builds request body from account and user context.
  • App calls POST API for bill explainer eligibility and URL.
  • UI displays CTA only when eligibility === true.
  • On click, app navigates to web utility route with Bill Explainer payload.
  • Web utility opens Bill Explainer URL externally and returns to previous screen.

3. Bill Explainer Flow Chart Diagram

This is the end-to-end functional flow from screen load to rendering and navigation.

flowchart TD
  A[Screen opens BillingBreakDownScreen] --> B{accountDetails present}
  B -- No --> C[Wait for accountDetails]
  B -- Yes --> D[Build requestBody]
  D --> E[Call POST api/GetBillExplainer/Get]
  E --> F{API call successful}
  F -- No --> G[Set showBillExplainer false and stop loading]
  F -- Yes --> H[Store API response in state]
  H --> I{eligibility is true}
  I -- Yes --> J[Set showBillExplainer true]
  I -- No --> K[Set showBillExplainer false]
  J --> L[Render Bill Explainer CTA in footer]
  L --> M[User taps Bill Explainer link]
  M --> N{be_url exists}
  N -- No --> O[Log link not available error]
  N -- Yes --> P[Navigate to ArticalWindowUtility]
  P --> Q[Open be_url in external browser]
  Q --> R[Go back to app screen]
Diagram Notes
  • Loading state: While API is running, CTA area shows skeleton placeholder.
  • Eligibility gate: CTA is shown only when res.eligibility is true.
  • Navigation behavior: Bill Explainer URL is opened externally (device browser), not kept inside embedded WebView.

5. How API Response is Rendered

5.1 Rendering Logic

  1. Footer checks explainerLoading and shows skeleton while request is in-flight.
  2. If not loading and showBillExplainer === true, footer renders CTA text + Bill Explainer link.
  3. When user taps link, app validates be_url and navigates with params.
  4. ArticalWindowUtility detects Bill Explainer and opens URL in external browser.

5.2 CTA Render Snippet

{showBillExplainer ? ( <Text onPress={() => renderBillExplainerLink(navigation)}> Bill Explainer </Text> ) : null}

5.3 Navigation Snippet

navigation.navigate('ArticalWindowUtility', { name: "Bill Explainer", url: data.be_url, });

5.4 External Open Behavior Snippet

if (name === 'Bill Explainer' && url) { Linking.openURL(url) .finally(() => navigation.goBack()); }
