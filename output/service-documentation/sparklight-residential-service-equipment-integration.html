Manage Equipment chooses the first qualifying Eero device before any qualifying modem. It separately transforms all Eero devices for My Add-ons. This is list-order selection; it does not check online status, network ownership, capabilities or reboot support.

04 · Leased, customer-owned and add-on conditions

Leased vs Owned

equipment.subscriber_owned === "R" ? "LEASED" : equipment.subscriber_owned === "P"

Observed implementation: “R” produces the LEASED label. “P” produces a boolean expression, not an OWNED string; booleans render no text in React. Other values likewise produce no ownership text. A badge wrapper is still rendered when equipment exists. The current code does not gate reboot by ownership; either leased or purchased equipment can expose the row if selected.

My Add-ons and Modem Speed

hasEeroDevice is true when the transformed Eero list has at least one entry. It enables My Add-ons and reveals the Modem Speed tab. Add-ons start expanded; the header toggles expansion and rotates the chevron. Rows display model and identifier with separators. showConnectionStatus defaults to false; this screen does not pass true, so “Connected” is not displayed or measured.

Code gap: MyAddons renders Touchable without importing it in the reviewed file. The list logic is implemented, but an actual Eero render can fail unless a binding is supplied elsewhere. This is a static source finding, not a runtime-tested conclusion.

05 · Modem reboot state machine and API

Confirmation to Result

Confirmation
→
Loading
pending=true
→
API accepted
Success
or
Rejected / invalid
Failure → Retry

Opening RebootModem only displays confirmation. Pressing Reboot Modem starts the POST. The confirmation warns that service will be briefly interrupted; Cancel returns to the previous screen.

POST api/ModemReboot
Authorization: Bearer <session token>
Content-Type: application/json
CallingApp: MobileApp

{
  "ip": null,
  "AccountNumber": "<current session account>"
}

ip becomes null for null, missing or whitespace-only input; other values are trimmed strings. Account number and token must be present and nonblank. The path shown from My Equipment and Services supplies no IP to Manage Equipment, so the normal path passes undefined and posts null. There is no IP-format or selected-device/MAC validation before reboot.

Checkpoint Acceptance / behavior
Duplicate tap pending.current prevents overlapping requests. It is cleared in finally.
Loading Status becomes loading; Reboot Modem and Cancel actions are disabled. Header Back and Modem Help remain in the shared layout.
Response Body must exist, body.error must be falsy, Number(statusCode) must be 200 or 202, and result must be boolean true. A string “true” does not pass this reboot check.
Success Shows “Modem Reboot Successful!” and a return action. This state follows the response check immediately. No follow-up GET verifies restart, modem reachability or reconnection.
Failure Any thrown transport/session/validation error, or an injected onReboot callback returning false, shows a generic failure alert. Retry invokes the same guarded operation; Cancel goes back.
Leaving screen mounted guard prevents state updates after unmount. It does not cancel the in-flight POST or undo an accepted reboot.
Automatic retry Speed-test service config sets skipRetry:true. Timeout/network/5xx are not automatically replayed. Shared 401 refresh/replay handling is still separate.

What the Client Does Not Check

There is no ownership-based eligibility check, no online/offline preflight, no eero-versus-modem reboot capability check, no reboot-completion poll and no local 10-minute wait. The selected card gates whether the button is offered; the backend response determines the success/failure state. The help text’s “up to 10 minutes” is guidance, not a timer or API condition.

Session, timeout and retry checkpoints

All documented wrapper endpoints are relative to Config.API_ACP_BASEURL. _axios defaults: JSON Content-Type, CallingApp:MobileApp, withCredentials:false and a 15-second timeout. Calls supply Bearer authorization from the stored session. Actual environment hostnames and tokens are intentionally excluded.

Checkpoint Behavior
Speed API preflight Account/token required; Ookla additionally requires userName; Eero history uses userId or account fallback. Download/upload must be valid nonnegative finite numeric strings/numbers; speed service validates without rounding/coercing originals.
401 refresh The interceptor refreshes the token once for a request, queues concurrent failures, updates authorization and replays the request. Refresh failure clears auth/session data and resets navigation to Splash.
skipRetry:true All speedTest.service operations set this, including reboot, start, history and GETs. It disables timeout/network/5xx retries; it does not bypass the earlier 401 refresh-and-replay branch.
Other API retries Equipment, usage, service details and outage calls use general retry behavior: timeout, Network Error or HTTP ≥500 can trigger up to three retries, with 1/2/4-second delays. No general retry for other 4xx.
Logging Speed API wrapper logs operation, stage, status and failure reason, then rethrows. This document describes source checks; it does not assert real endpoint availability or backend response correctness.

MySpeedCard defaults to WiFi, fetches the last stored Ookla result on initial load, selected-tab change, focus and refreshKey change, and shows the last-run timestamp. Test Speed opens WifiSpeedTest. The WebView loads local OOKLA_HTML with PORTAL_BASE_URL as its base URL and embeds the HTTPS Ookla iframe. Measurement is performed by that widget; the application’s POST saves the completed measurement, not a command to start Ookla.

Widget: https://cableone.speedtestcustom.com
GET api/get/OoklaSpeedtest/:accountId/:userId
POST api/post/OoklaSpeedtest
{
  "accountId": "<session accountNumber>",
  "userId": "<session userName>",
  "download_MBs": 980.4,
  "upload_MBs": 54.69,
  "ping_ms": 11,
  "jitter_ms": 22,
  "host": "<widget host or null>"
}

Payload values above are illustrative. Despite the API field name MBs, the bridge normalizes speeds to Mbps; it does not convert to megabytes per second.

Checkpoint Rule
Iframe bridge event.source must be the Ookla iframe window and event.origin must equal the exact Ookla origin. Completion requires config.testId, end.timestamp, and device.platform === “speedtest-custom”.
Native parser JSON must parse. type must be “ookla-complete”; unrecognized types or missing platform/testId/timestamp return null and do not save. Invalid units or measurements throw.
Speed units Mbps ÷ 1; Kbps ÷ 1000; bps ÷ 1,000,000. Any other unit throws.
Measurements Only number/string, nonblank, finite and nonnegative accepted. Zero is valid. Optional ping/jitter are null if absent. host is a string or null.
Deduplication A Map keyed by testId tracks saving/saved/failed within the mounted screen. Duplicate completion messages do not repeat the POST. It is not persisted across screen mounts; testId is not sent in the save payload.
Successful POST Accepts literal body true, or historyResults.statusCode numerically 200 with historyResults.result true or string “true”. The wrapper’s error field can contain “Success”, so save validation deliberately checks status/result.
Successful GET HTTP 204 or absent body means no result. Otherwise validates testResults.download_MBs / upload_MBs and reads testResults.createdOn. This getter does not validate a wrapper statusCode.

Failure and Recovery

Failure UI / recovery
WebView load/HTTP error “Unable to load speed test”; Retry clears failure and increments the WebView key to reload.
Malformed JSON, bad units or invalid measurement Invalid result alert asks the user to run the test again; no save-retry action. Some missing completion fields are silently ignored instead of showing this alert.
History POST failure “Your test completed. Retry saving without running another test.” Retry Saving Result resends the cached measurement only after its prior state is failed.
Latest result GET failure My Speed shows “Unable to load the latest result.”; Test Speed remains available after loading ends.
No saved result Shows “No speed test results yet.” and placeholder download/upload values.
Cancel / Back Navigates back. Mounted guards avoid late UI updates; an already sent save request is not cancelled.

09 · Eero / modem speed: GET baseline → POST start → GET poll → POST history

Availability and Request Sequence

Manage Equipment offers the Modem Speed tab only when the equipment response yields at least one qualifying Eero device. WiFi remains available without Eero. Changing tabs is disabled during last-result loading. The current Test Speed route passes no idType or networkId, so ModemSpeedTest uses its default account identity.

GET previous result
→
POST start
→
GET fresh result
poll up to 24 times
→
POST history
Operation Method / contract / acceptance
Latest saved result GET api/GetEeroSpeedTestHistory/:accountId. 204/absent body returns null. Reads download_MBs, upload_MBs, createdOn; validates speeds.
History fallback getLatestEeroResult tries history first. Missing or failed history falls back to Eero results except HTTP 401/403, which are rethrown.
Current result GET api/get/EeroSpeedtest, query {idType, id, accountNumber}, timeout:0. 204/absent body/empty data returns null. error must be falsy; statusCode, if supplied, must be numerically 200. data must be an array with valid dates. Selects newest date and validates down_Mbps/up_Mbps.
Start test POST api/post/EeroSpeedtest, body {idType,id,accountNumber}. error must be falsy and statusCode numerically 200 or 202. Does not require result:true.
Identity idType must be “account” or “network”. account uses session accountNumber; network requires nonblank networkId. accountNumber remains included in both modes.
Poll freshness Before starting, obtains the previous result. Each poll must have updated timestamp newer than previous.updated, if previous exists. Old results cannot be saved just because start returned 202.
Poll schedule First GET is immediate; later attempts wait 5 seconds. At most 24 GETs after the start, giving 23 inter-attempt waits (~115 seconds) plus request durations. Since result GET uses timeout:0, this is not a strict 2-minute timeout.
History save POST api/InsertEeroSpeedTestHistory, fields accountId, userId, download_MBs, upload_MBs, ping_Ms, jitter_Ms, host. userId is stored userInfo.userId, falling back to accountNumber. Missing ping/jitter default to 0; missing host to empty string.
History acceptance Literal body true or historyResults.statusCode numerically 200 and result true/string “true”. Fresh measurement returns historySaved:true or false. History-save failure keeps successful measurements visible.
Additional details getter GET api/Eerospeedtest/details with same identity query. Checks statusCode=200; reads detail.download_Result/upload_Result/tstamp/id. This operation is defined, but the reviewed MySpeedCard/runEeroSpeedTest paths do not call it.

Screen State and Cancellation

ModemSpeedTest starts automatically on mount. pending prevents overlapping runs, including pull-to-refresh. The action is disabled while running; errors show Retry Speed Test; completion shows Run Speed Test Again. Missing download/upload results cause failure. Unmount is checked before start continuation and during polling; it stops further client work at the next check, but does not cancel an already issued backend test or in-flight GET.

A failed history save is a partial success: results and completion remain visible with “Result not saved”. The current screen does not offer a history-only retry for Eero; Run Speed Test Again starts another measurement. This differs from Ookla’s Retry Saving Result.

Gaps Preserved in This Documentation

1. Initial-route capitalization differs from the declared Manage Equipment route. 2. Ownership “P” is a boolean expression rather than an OWNED label. 3. MyAddons uses an unimported Touchable. 4. Reboot confirmation has no local capability/ownership/online check and success has no reconnection poll. 5. Equipment errors and empty equipment share a fallback state. 6. Resolved outage error bodies are not distinguished from no outage. 7. Normal navigation supplies no modem IP/network ID, so reboot sends ip:null and Eero speed defaults to account identity.
